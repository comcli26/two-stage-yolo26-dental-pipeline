# A Two-Stage YOLO26 Pipeline for Tooth Instance Segmentation, Detection of Teeth with Visible Caries, and Geometric Association in Intraoral Photographs

This repository contains the full computational pipeline, trained-model artifacts (via release/links), and result tables/figures for the study *"A Two-Stage YOLO26 Pipeline for Tooth Instance Segmentation, Detection of Teeth with Visible Caries, and Geometric Association in Intraoral Photographs"*.

The pipeline integrates three stages over intraoral photographs:

1. **Tooth instance segmentation** (8 structural tooth categories) using YOLO26n/s/m-seg.
2. **Detection of teeth with visible caries** (single class) using YOLO26n/s/m-det.
3. **Geometric association** between caries detections and segmented tooth instances, using a calibrated centroid → overlap-ratio procedure (τ, δ).

> This is a computer-vision feasibility study. Reported metrics describe algorithmic performance with respect to the reference annotations used and do **not** constitute clinical validation or diagnostic evidence.

## Pipeline overview and execution order

The notebooks must be run in the order below, since each stage consumes the output of the previous one.

| Stage | Notebook(s) | Produces |
|---|---|---|
| 0a — Data preparation (caries) | `Tratado_0_Deduplicacion_Cruzada` → `Tratado_1_dataset_Ahmed` → `Tratado_2_dataset_Ahmed` → `Tratado_3_dataset_Shweta` | Final caries-detection dataset (1664 images, 4569 boxes, 255 negatives) with no cross-partition / cross-dataset leakage |
| 00b — Data preparation (segmentation) | `Tratado_0_Verificacion_Participante_Segmentacion` → `Tratado_1_dataset_Segmentacion_Dientes` | Participant/session-level leakage check, re-split dataset (1751 images: 1223/284/244), oversampled training set |
| 01 — Tooth segmentation | `pipeline_YOLO26_dientes` (unified, resumable) | Trained YOLO26{n,s,m}-seg models, class-distribution and comparison tables |
| 02 — Caries detection | `entrenamiento_yolo26_deteccion_caries`, `ablacion_negativos_yolo26m_det` | Trained YOLO26{n,s,m}-det models, comparison table, external-negatives ablation |
| 03 — Geometric association | `pipeline_asociacion_geometrica` | τ/δ calibration, final accuracy/coverage tables, timing table, qualitative figure |

Data preparation and dataset provenance are documented in [`docs/data_availability.md`](docs/data_availability.md). Environment/library versions are documented in [`docs/environment.md`](docs/environment.md).

## Main results

### Tooth instance segmentation (test set, 244 images)

| Model | Mask mAP@50 | Mask mAP@50–95 | Precision | Recall |
|---|---|---|---|---|
| YOLO26n-seg | 0.947 | 0.841 | 0.925 | 0.895 |
| **YOLO26s-seg (best)** | **0.962** | **0.863** | **0.953** | **0.897** |
| YOLO26m-seg | 0.950 | 0.856 | 0.919 | 0.903 |

### Detection of teeth with visible caries (test set, 242 images)

| Model | Precision | Recall | mAP@50 | mAP@50–95 |
|---|---|---|---|---|
| YOLO26n-det | 0.868 | 0.896 | 0.927 | 0.729 |
| YOLO26s-det | 0.874 | 0.894 | 0.915 | 0.717 |
| **YOLO26m-det (selected)** | **0.844** | **0.915** | **0.927** | **0.721** |

### Geometric association (calibrated on validation, evaluated on 777 test-set detections)

| Parameter / metric | Value |
|---|---|
| τ (overlap threshold) | 0.10 |
| δ (ambiguity margin) | 0.02 |
| Accuracy | 0.9909 |
| Coverage | 0.9858 |
| Pipeline latency (segmentation + detection + association) | ≈105 ± 42 ms/image |

## Reproducibility notes

- All notebooks were executed on Google Colab. Dental segmentation and caries detection were trained on a Tesla T4 GPU. The final geometric-association pipeline (Table 16 timings) was run on an NVIDIA L4 GPU (23,034 MiB) — see [`docs/environment.md`](docs/environment.md)).
- File paths inside the notebooks reference the original Google Drive folder structure used during development (`/content/drive/MyDrive/UNIVERSIDAD/...`). Adjust the base path constants at the top of each notebook to your own environment before re-running.
- Some cells (manual double-review annotation with `ipywidgets`, sensitivity/diagnostic checks) are marked in each notebook as one-time or diagnostic steps and are **not required** to reproduce the final tables — their outputs are already saved as CSVs under `results/`.
